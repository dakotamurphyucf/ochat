# ChatML and ChatMD highlighting

`Language_highlighting.Highlight_snapshot` produces version 1, presentation-neutral lexical spans from exact captured bytes. A ChatML result carries its `Chatml_source` ID and digest. A ChatMD result carries the `Chatmd_parser_input` identity, an explicit authored or effective view, and that view's digest. Its nonempty half-open ranges count bytes; no output can be reassigned to another source revision. The source string is borrowed immutably. Editor UTF-16 projection uses `Chatml_editor_position` against the exact capture; invalid UTF-8 keeps byte-mode highlighting available and makes UTF-16 projection unavailable. Neither highlighting nor conversion changes compiler admission.

Roles describe spelling only. `Identifier` does not certify a binding, type or definition; `Reached_eof` means the lexical scan reached the end, not that the parser accepted it. Incomplete comments, strings, RAW blocks, script bodies and tags retain truthful lexical ranges and issues. A host selects positive source/owner, span, issue, nesting and lexical-work limits. The scanner uses bounded lookahead, advances monotonically, checks capacity before retaining spans, and polls its checkpoint during input-sized work; cancellation propagates. `Truncated` gives a retained prefix boundary and reason, so clients must not extend its roles into the suffix. `contains_span` checks membership in the exact snapshot, not merely a same-length range.

The ChatMD scanner uses the authoritative `Chatmd_ast.tag_of_string_opt` vocabulary. Some tags are valid only in certain parser contexts; their lexical color is not proof of a valid declaration. RAW content stays raw, including apparent closing tags inside `RAW|...|RAW`; a tolerant script close may have whitespace before `>`. An inline `<script>` body is lexed as ChatML only when its raw opening tag explicitly has `language="chatml"` and no `src`; other languages and external-source declarations receive a generic script-body role. This is presentation over exact raw bytes, not a claim that embedded code compiled or that a transformed body has a contiguous parent range. [OCH-259's parser-owned extraction map](../design/chatml-authoring-services.md#queries-and-incomplete-input) supplies exact, approximate or unmappable authored/effective projections. External `src` code is highlighted against its own captured source, with the declaring attribute retained as a related site by the service. No highlighter opens paths, fetches packages or executes code.

`Terminal_highlighting.Highlight_grammars.add_chatml` and `add_chatmd` embed dedicated TextMate assets (`source.chatml` and `text.chatmd`) in the installed library. The loader resolves `chatml`, `chatmli` and `chatmd` directly; ChatMD is no longer silently treated as HTML, and ChatML is not colored with an OCaml grammar. `add_chatmd` also installs the ChatML include for explicitly selected inline bodies. The assets cover selected keywords/operators, variants/type variables, strings, nested-comment scopes, official markup, attributes, RAW and inline script display. They are display hints: TextMate's regex/line-state model cannot certify conditional tag validity, arbitrary transformed-source maps or parser success. A custom optional grammar remains a separate explicit frontend policy.

The mandatory terminal source path uses `Terminal_source_highlighting.render` over the bounded lexical snapshot and the shared terminal theme. It does **not** call TextMate/Oniguruma for ChatML or ChatMD. The adapter preflights zero-based line count and byte length, then walks source bytes and ordered spans linearly with checkpoint polling. It strips CR, LF and CRLF terminators from display rows without changing source ranges. It leaves other control bytes untouched; each frontend sanitizes them before `Notty.I.string`. The chat TUI routes bundled `chatml`, `chatmli` and `chatmd` code fences through this path with its active theme, highlight cache and surrounding layout. It retains an immutable per-registry baseline for each bundled grammar; an explicit override of one language keeps that language on the existing TextMate path without affecting the other. The main renderer and detached worker each own their baseline. Its preview policy admits at most 65,536 source bytes, 4,096 bytes per line and 2,048 lines. Lexical work truncation leaves the scanned prefix styled and visibly marks the suffix; admission or output limits produce a bounded plain prefix plus `[source preview truncated]`. The chat frontend replaces controls and malformed UTF-8 only in display spans; captures and lexical ranges remain exact. Other code-fence languages retain the existing TextMate path. The reusable adapter lets the Eio/Notty REPL supply its own captured source and host limits in OCH-255.

The generic `Highlight_tm_engine` remains available for TextMate consumers, including direct clients and optional user grammars. Its tokenizer calls Oniguruma without an interruption hook inside one regex. Polling between lines or setting an input byte cap does not make a hostile regex preemptible; no hard cancellation/work guarantee is claimed for that generic path. The installed ChatML/ChatMD patterns avoid nested unbounded backtracking, and focused tests exercise their actual scope output, but the deterministic terminal admission guarantee comes from the lexical scanner path.

Focused validation is in `test/language_highlighting`: it compares selected complete ChatML token byte boundaries with the compiler lexer, checks lexical roles and exact ChatMD views, malformed prefixes and work limits, inline versus generic script bodies, cancellation, installed TextMate scopes/aliases, terminal line reconstruction and TUI preview limits. Existing `test/chat_tui_highlighting` covers generic grammar compatibility and optional discovery. M5's final integrated website and workflow checks remain OCH-254.
