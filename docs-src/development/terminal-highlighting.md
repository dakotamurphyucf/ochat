# Shared terminal highlighting

`Terminal_highlighting` owns the Notty styles, GitHub-dark TextMate theme, grammar loader, span engine and embedded grammars used by terminal frontends. A frontend creates its own `Highlight_tm_loader.registry`, adds only the grammars it needs with `Highlight_grammars.add_*`, then attaches that registry to a `Highlight_tm_engine.t`. The engine returns per-line `(Notty.A.t * string)` spans or scoped spans; missing registries, unknown languages and tokenizer errors retain the existing plain-span fallback. ChatML and ChatMD grammar assets are supplied separately by OCH-135; an OCaml grammar is not treated as their substitute.

The shared loader accepts decoded `Jsonaf.t` and performs no filesystem I/O. A frontend that accepts external grammar paths reads them with its Eio filesystem capability, parses JSON, and calls `add_grammar_jsonaf`. Each frontend owns its registry and engine. An engine borrows its mutable registry: adding a grammar affects all engines holding that registry, so frontends use distinct registries for isolation and confine registry mutation to their owner. Theme rules and their compiled index are immutable. Each engine owns a resolver with at most 4096 cached scope sets and 256 KiB of encoded keys; collision-free length prefixes keep separate scope groups distinct, and a saturated cache computes without retaining new entries. Its atomic immutable snapshots permit concurrent reads without sharing a process-global mutable table. `Chat_tui.Highlight_*` paths re-export the same types and functions for compatibility; its process-wide `Highlight_registry` and generation-based `Renderer_highlight_engine` remain chat renderer policy. The legacy `Chat_tui.Highlight_tm_loader.add_grammar_jsonaf_file` is retained only for source compatibility and is not part of the shared library.

The grammar assets are embedded at build time with their vendored license/update material, so bundled highlighting does not depend on the process working directory. Optional grammar discovery and custom files stay in Chat_tui's Eio-owned policy. `Markdown_fences` remains chat-owned because it segments chat message prose and code fences for that renderer; the REPL source view consumes TextMate spans without chat message layout. The engine preserves source text in spans but does not sanitize control bytes or bound input; the terminal frontend must do both before passing spans to `Notty.I.string`. `notty_eio` and `notty_scroll_box` are already separate libraries. REPL core, receipts and service DTOs have no Notty dependency.
