# Captured document foundation

Owned ChatMD parsing records each included `<doc>` occurrence at its actual parser
input and byte range, together with its registering Root and content slot. Repeated
imports have separate occurrences. Message display context does not select a native
root or change declaration ownership. Ordinary parsing does not acquire document
content.

`<doc src="./guide.md" local capture />` selects frozen local content;
`<doc src="builtin:chatml" />` selects the reviewed embedded ChatML starter. Unmarked
documents retain their dynamic behavior. The starter's examples are compiled in the
catalog test. Other builtin identifiers, including `skills`, currently reject until
reviewed instruction assets exist. No capability or tool grant follows from an import.

The pure content owner receives observed local bytes or an authentic embedded asset,
uses bounded conversion, and stores final rendered bytes in a separate SHA256 pool.
Its named metadata retains every occurrence, including dynamic slots and Roots with
no documents. Parser-input identities, exact ranges, source selection and local/
cleanup/Markdown flags bind each stored output to its actual occurrence. Admission
validates the complete inactive inventory and preserves unknown metadata fields.
Supplying local bytes to a pure constructor does not prove a native read or grant
filesystem authority.

Materialization matches the actual selected Parsed and returns a separate projection
whose captured slots contain literal text. It retains the original Parsed for script
declaration ownership and preserves dynamic slots and other message fields. Its
complete receipt includes input reconciliation, occurrence validation and final tree
projection; the projection's own phase count is already included. Occurrence counts
include dynamic slots, and output bytes count each selected captured literal even
when its physical payload is shared. Replay input bytes and conversion nodes are
zero because this phase performs no acquisition or conversion. Captured bytes are
not looked up or converted again. Adoption preserves inactive parent records, exact
payloads and compatible unknown fields, with both input metadata documents and the
merged output admitted under one bounded invocation.

Input/output and logical-work ceilings aggregate all occurrences; deduplicating equal
physical output does not reset them. Named metadata construction uses the shared
Document_schema.Encoding measure-before-construct owner. Read-only parser-input v1
identity hashing is shared with executable custody and preserves its existing wire.

This foundation does not yet install document content in an artifact or replace live
history imports. The owner integration adds retained-directory acquisition, joint
artifact storage bounds/transactions, semantic revision identity and fresh/retained
child materialization before history admission.
