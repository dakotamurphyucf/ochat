# Captured document custody

`<doc src="./guide.md" local capture />` captures bounded local content at explicit source preparation. `<doc src="builtin:chatml" />` captures the reviewed build-time ChatML starter. Other builtin identifiers, including `skills`, reject until real supported instruction content is curated. Unmarked document imports preserve their existing dynamic behavior; remote content is never captured automatically.

Document acquisition borrows the same retained original-source owner that captured the prompt. Its actual parser-owned occurrence and declaring input determine the portable member path. Display `source_context`, artifact filenames and working-directory lookup never supply native authority. Immutable acquisition results retain no native owner, preprocessor or callback.

Content is a separate named metadata/private payload inventory beside executable parser/program custody. Both participate in the same artifact transaction, complete manifest ceiling and joint 256-file / 8 MiB payload inventory. This is a retained payload allowance, not an OS disk quota: the authored tree has established redundant storage copies. Original document metadata extensions and inactive Root records survive load, copy and child selection. Every complete content manifest, including unknown metadata and exact private inventory, enters semantic revision identity before installation.

Fresh preparation resumes the original content work allowance after native capture, validates its correspondence with actual parser/program custody, and validates registering Roots. It then replays immutable captured parser bytes against the final artifact directory and materializes the selected literal projection before installation, using the same remaining work. No filesystem reads or preprocessing occur in that replay. Installation verifies the actual final tree before attaching that exact parser/projection. Validation and runtime activation have distinct logical occurrence/output ceilings; all performed work remains cumulative. Physical output dedup does not exempt repeated logical occurrences or output bytes.

Restart requires explicit host content policy. It independently validates the complete stored active/inactive content inventory, reconciles authentic retained parser inputs, then projects the selected Root using remaining work. An owned parser requesting captured or builtin content rejects a missing content bundle. Legacy artifacts without owned parser metadata retain their existing behavior and do not acquire these guarantees retroactively. Invalid present content never falls back to originals, an installation lookup or dynamic rendering. The literal projection reaches initial-history conversion with the original parser declaration identity retained; runtime consumers can reuse `Prompt_revision.document_projection` without reparsing.

`Prompt_catalog.create` receives a fixed `content_limits` restoration policy. Catalog cache misses forward it to the same Builder replay used for direct restoration; failed admission never enters the cache. Cache hits reuse the already validated immutable projection, without repeating conversion or resetting an unfinished replay budget. Changing the policy requires constructing a new catalog. Daemon composition forwards its explicit host option to that catalog; artifact metadata cannot select a more permissive policy.

Retained child preparation selects the actual child Root inside the verified parent artifact directory and keeps complete immutable content custody. Its resource revision verifies the exact child authored tree and transfers the already validated parser/projection without resetting the content allowance. Changing prepared role graphs adopts against the same actual Root. A separately installed child restart replays under its own artifact directory and explicit policy. Original files, parent registries and builtin lookup are unnecessary for retained replay.

Current integration boundary: SourceOwner exposes the bounded capture operation and Builder receives an immutable preparation hook. Catalog/session host composition must call project and document acquisition inside the same live scope before publication and supply explicit policy for content-bearing restore. Missing acquisition rejects captured/builtin slots; genuinely all-Dynamic legacy prompts keep their absent-content identity.
