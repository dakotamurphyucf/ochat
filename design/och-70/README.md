# OCH-70: bounded ChatML correctness audit

Audit of base `58e9d2c5567d596fbe52ba1041e37d12dbde102b` for M4-R0. This is an executable, source-backed first audit, not a proof of type soundness or a complete compiler/security qualification. No compiler/runtime behavior was changed. Findings must become concrete follow-up work before affected feature acceptance; research completion does not implement a fix.

Five confirmed categories emerged from minimal positive/negative comparisons: module/record representation disagreement, loss of exact record-pattern coverage through widening, loss of variant payload arity for unit, missing deferred equality obligations, and eager module self-reference before export publication. See [findings](findings.md), [coverage matrix](coverage.md), [verification](verification.md), and [structured follow-ups](followups.json).

The reproducer suite is `test/och70_chatml_audit`. Its expect outputs deliberately preserve current defect observations. A fix owner must replace the affected observation with the chosen correct rejection or execution behavior, preserve the paired positive case, and expand the indicated verification. These observations are not permanent language contracts. Ordinary runtime failures such as division by zero, out-of-range indexing and malformed supplied JSON are separately labeled; acceptance by a checker does not promise those operations succeed.

Each confirmed runtime mismatch was reproduced through parse → check → resolve → evaluate, rather than through manually forged ASTs or a bypassed checker. Compiler-policy observations use the production Eio-domain compilation API. Existing parser/typechecker/runtime and host-control suites provide broader evidence, with exact commands and results recorded separately. No provider calls, real tools, credentials, networking, desktop work or shared package changes were involved.

OCH-73/M4-R1 should consume these findings as design inputs while unrelated discovery continues. OCH-98/M4-T01, OCH-100/M4-T02 and semantic-service consumers must retain the applicable unresolved correctness blockers. A source-resolution or authoring extension cannot erase an accepted-program/runtime disagreement by documenting only the happy path. Host authority and admission remain separate: these examples demonstrate language correctness/contract failures, not sandbox escapes.
