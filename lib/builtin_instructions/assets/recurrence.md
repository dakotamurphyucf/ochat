# Recurring work

Use only recurrence tools explicitly supplied to this session. `recurrence_list`,
`recurrence_get`, `recurrence_status` and `recurrence_history` read this invoking
controller. They do not choose another controller or grant target access. Status
labels retained controller evidence separately from a separately authorized target
snapshot; missing detail or unknown outcome never proves no effects.

Read the current generation, catalog revision, source and lifecycle basis before
Create/Edit/Resume. Echo them and the entry control revision exactly; never refresh
CAS silently. Create starts paused. Explicit Resume enables future work. Pause
fences new launches; Cancel permanently retires the identity. Neither promises to
cancel admitted or external effects. Keep an acknowledged idempotency key AND its
complete original request unchanged for retry. Use a new key for an intentional
Edit, which captures the currently selected source once.

An Existing target names a full host/session reference and ordinary input. An
Authored target names a worker declared normally in ChatMD, for example
`<tool name="weekly_worker" agent="workers/weekly.chatmd" local persistence="persistent"/>`,
with one versioned lifecycle moderator. Select `single_turn` or `workflow` explicitly.
Its configured project, compiled code and
private tools are captured under the actual selected resource loan. Captured bytes
and receipts do not grant current source, workspace, native tool or execution
permission. Operator Artifact targets remain available through the host API.

Use explicit schedule and policy data: fixed rate preserves the interval phase;
fixed delay waits for observed definitive completion. Calendar rules require a
named timezone and gap/repeated-time policy. Missed work is bounded by policy,
pending capacity and serial target exclusion. Never substitute ambient timezone,
promise unbounded catch-up, or re-enable a stopped controller automatically.

The configured execution host must remain available and authorized. Controller
Stop or absence holds future work; process death does not replay an interrupted
occurrence. A timer is not completion evidence. Report actual admissions/outcomes,
unknowns, interruptions and unavailable/denied target details honestly. There is
no general exactly-once external-effects or automatic rollback guarantee.
Importing this text or the pure Recurrence_requests package schedules nothing.
